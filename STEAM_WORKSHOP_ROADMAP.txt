[h2]Claude Desktop issue and beta.5[/h2]

After the beta.4 live-save gate passed, regular Claude Desktop Home-chat testing exposed a separate client compatibility blocker on Windows. The MCPB installs, enables, and launches, but Claude Desktop cancels its MCP initialization after 60 seconds before exposing the tools. The identical server responds immediately when invoked directly, and Claude Code plus Codex continue to work.

Beta.5 replaces the hand-written stdio layer with the official MCP SDK transport and packages the same self-contained server for Workshop/direct-path and MCPB use. The first live attempt exposed a second startup condition: Claude Desktop loads the Node entry point through its UtilityProcess wrapper. A dedicated MCPB entry point fixed that condition, and a fresh Windows Home conversation then exposed the PWS integration and returned the live VWE1 state.

[h2]What remains before 0.4.0[/h2]

[list]
[*]Publish the Workshop update, matching GitHub release, installation notes, and full changelog.
[/list]

The release fixes the known B12 mode-detection mismatch by reading advanced-popularity mode from PWS's [code]gameworld[/code] data, evaluates worker return dates against a future show's actual air date, verifies stable leader state after adding a member, and corrects/reads back supported generic worker-signing terms. All 79 automated tests and all 13 live read-only checks pass. VWE1 now reports Regional correctly, its injury/rehab boundary checks pass, and a reversible leader add/remove persisted and cleaned up exactly. The installed 0.4.0 MCPB also connected from a fresh Claude Desktop Home conversation and returned the correct live state. Receipt-bound confirmations are deferred as a broader post-0.4.0 protocol change; previews, explicit confirmation, apply-time revalidation, and post-save verification remain in place.

Tournament management, complete contract negotiations, incoming rival-offer responses, and network or TV-deal management are valuable future features, but they are no longer being treated as blockers for 0.4.0.

[h2]Storyline attribution finding[/h2]

Version 0.3.0 added a diagnostic for completed segments that appear to be missing storyline-history entries. Beta testing then fixed false positives caused by escaped characters and storyline-date boundaries.

The remaining historical outage was traced to Concert Bands Pro replacing PWS's show-summary function. Storyline attribution resumed after that mod was disabled. Because the MCP server was not causing the simulation failure, 0.4.0 keeps the diagnostic and avoids an unsafe database repair.

[h2]Client update reminder[/h2]

Steam updates only the in-game PWS plugin.

Claude Desktop users must also install the matching [code].mcpb[/code] from the [url=https://github.com/Distortik/pws-mcp-server/releases]GitHub release[/url] and restart Claude Desktop. Installing a newer package with the same extension identity normally upgrades the existing installation; uninstalling first should only be needed as a fallback. Beta.4 remains incompatible with regular Home chat; beta.5 fixes and live-verifies that path.

Claude Code and Codex users can keep their MCP configuration pointed at the stable Workshop plugin folder. They can paste the setup request above into the client and ask it to locate, configure, and verify that path automatically instead of editing settings manually. Restart the client after an update so it reloads the current server and tool catalogue.
