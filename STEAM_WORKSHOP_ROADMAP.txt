[h1]PWS MCP Server Roadmap — Beyond 0.5.0[/h1]

[h2]Where the project stands[/h2]

Version 0.5.0 is the current production release and the largest base-game expansion so far. It moves PWS MCP Server beyond save inspection and show booking into practical company management while retaining preview-first, revalidated, and verified changes.

This roadmap describes direction, not a promise that every item will ship together. Features that change a save will be released only after their native PWS behavior and persistence have been established.

[h2]0.5.0 milestone — delivered[/h2]

[list]
[*]Reliable unfinished-show discovery across both native event-instance paths
[*]Callable connection, transport, version-pair, and loaded-save diagnostics
[*]One-call show auditing and roster-rotation analysis
[*]Accurate Occasional Wrestler handling and cash-aware hiring guidance
[*]Ordered multi-person entrances and eliminations
[*]Established-team discovery, company registration, and full tag-team management
[*]Brand lifecycle management, worker assignments, and commentary-team defaults
[*]Championship creation, editing, retirement, reinstatement, awarding, and vacation
[*]Purpose-built contract modification and immediate signing
[*]Purpose-built storyline creation and editing
[*]Event-series discovery and editing, show scheduling, and rescheduling
[*]Network availability and deal discovery, plus native deal cancellation
[/list]

[h2]Next priority: stronger safety and clearer decisions[/h2]

[h3]Preview-bound approval receipts[/h3]

Current write tools preview by default, require explicit confirmation, revalidate the live target at application time, and verify what persisted. The next safety step is a short-lived approval receipt that binds confirmation to the exact preview, operation, and target state the player approved.

[h3]Richer change summaries[/h3]

Make complex previews even easier to judge by showing affected records, important side effects, and concise before/after values consistently across management tools.

[h3]Better recovery guidance[/h3]

When PWS rejects a native action or the live state changes between preview and application, return more specific next steps without hiding the original game error.

[h2]Next priority: deeper booking intelligence[/h2]

[list]
[*][b]Feud and storyline health:[/b] identify inactive members, missing recent development, repetitive pairings, and stories that are not represented on upcoming cards.
[*][b]Card variety:[/b] highlight repeated matchups, overused finishes, missing divisions, weak pacing, and workers who are booked in conflicting roles.
[*][b]Title planning:[/b] summarize contender activity, recent defenses, reign length, brand alignment, and championship visibility.
[*][b]Longer-horizon planning:[/b] compare several scheduled shows and suggest balanced worker rotation without silently changing the save.
[*][b]Tournament research:[/b] map native tournaments, rounds, participants, matches, and their links to booked segments before adding write support.
[/list]

[h2]Next priority: broader company operations[/h2]

[list]
[*][b]Contract renewals and negotiations:[/b] research offers, counters, rival bids, matching, declines, perks, and negotiation states while leaving hidden calculations to PWS.
[*][b]Network offers and renegotiation:[/b] extend the current network reads and cancellation support only where PWS exposes a complete native workflow.
[*][b]Division and roster planning:[/b] connect brands, championships, teams, stables, worker roles, availability, and recent usage into clearer planning reports.
[*][b]Financial context:[/b] improve read-only budgeting and payroll forecasts without introducing arbitrary balance edits.
[*][b]Moveset research:[/b] establish the supported native moveset categories and JSON behavior before considering verified editing.
[/list]

[h2]Quality-of-life direction[/h2]

[list]
[*]More focused tools for common multi-step workflows
[*]Clearer empty-state explanations so “nothing found” can be distinguished from connection, filter, or data-shape problems
[*]More compact results for AI clients with smaller context windows
[*]Expanded diagnostics for outdated clients and incorrectly configured server paths
[*]Continued performance work on large databases and long-running saves
[/list]

[h2]Known native boundaries[/h2]

[list]
[*]PWS stores one active presentation per contract, not a separate persona for every match.
[*]A championship or prize with [code]defendable = 0[/code] cannot be attached to a match; book the match without it and award the title afterward.
[*]New network offers, renegotiations, and full contract negotiation simulations remain in PWS while their hidden calculations are not exposed as complete native actions.
[*]World-editor operations such as arbitrary finances, worker attributes, relationships, venues, or raw database writes are outside the normal company-management scope.
[/list]

[h2]Release standard[/h2]

Every production update must pass:

[code]
Native PWS behavior research
        |
        v
Focused implementation and regression coverage
        |
        v
Full automated test suite
        |
        v
Installed live read and write verification
        |
        v
Restart and persistence checks where relevant
        |
        v
Matching Workshop and client packages
[/code]

[h2]Client update reminder[/h2]

Steam updates only the in-game PWS plugin.

Claude Desktop users must also install the matching [code].mcpb[/code] from the [url=https://github.com/Distortik/pws-mcp-server/releases/latest]GitHub release[/url] and fully restart Claude Desktop.

Claude Code and Codex users can keep their MCP configuration pointed at the stable Workshop folder, then restart the client after an update so it reloads the current server and tool catalogue.
