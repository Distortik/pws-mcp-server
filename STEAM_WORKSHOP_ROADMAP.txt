[h3]Stables, gimmicks, events, and shows[/h3]

[list]
[*]List, create, update, and dissolve stables while protecting PWS's minimum stable size.
[*]Browse database-specific gimmicks and assign a contract gimmick safely.
[*]Create event series, schedule show instances, assign venues, and cancel unfinished shows.
[*]Archive or restore event series without deleting completed or cancelled show history.

[h3]Wrestler personas[/h3]

[list]
[*]Browse a worker's native PWS alter egos, including preferred gimmick, picture, mask, promotion restriction, and valid dates.
[*]Switch one promotion contract to a selected persona or custom ring name without renaming the worker globally.
[*]Change a persona between promotion-specific and free use, with exact restoration support.
[*]Reject personas outside their native date range by default, with an explicit creative-sandbox override when requested.
[/list]

This supports cases such as selecting The Undertaker, biker Undertaker, Mankind, or Dude Love when those alter egos exist in the loaded database. PWS currently stores one active presentation per contract rather than a separate persona selection for every match.

[h2]Claude Desktop issue and beta.5[/h2]

After the beta.4 live-save gate passed, regular Claude Desktop Home-chat testing exposed a separate client compatibility blocker on Windows. The MCPB installs, enables, and launches, but Claude Desktop cancels its MCP initialization after 60 seconds before exposing the tools. The identical server responds immediately when invoked directly, and Claude Code plus Codex continue to work.

Beta.5 will focus on the stdio/SDK compatibility layer, add a real-client initialization regression test, and require regular Claude Desktop Home chat to expose the matching PWS tools before 0.4.0 can ship.

[quote][b]Temporary user-friendly workaround[/b]

Use Claude Code, Claude Desktop's Code tab, or Codex with the direct [code]mcp-server.js[/code] path. You do not have to edit configuration or guess the Steam library manually. Paste this request into Claude Code or Codex:

Locate the installed PWS MCP Server [code]mcp-server.js[/code] for the build I am actually using (Workshop, manual, or TEST). Configure your user-level MCP server named [code]pro-wrestling-sim[/code] to run it with Node, verify the saved entry, and tell me the exact path you selected. Do not guess the Steam library or edit unrelated MCP entries.
[/quote]

Tournament management, complete contract negotiations, incoming rival-offer responses, and network or TV-deal management are valuable future features, but they are no longer being treated as blockers for 0.4.0.

[h2]Storyline attribution finding[/h2]

Version 0.3.0 added a diagnostic for completed segments that appear to be missing storyline-history entries. Beta testing then fixed false positives caused by escaped characters and storyline-date boundaries.

The remaining historical outage was traced to Concert Bands Pro replacing PWS's show-summary function. Storyline attribution resumed after that mod was disabled. Because the MCP server was not causing the simulation failure, 0.4.0 keeps the diagnostic and avoids an unsafe database repair.

[h2]Client update reminder[/h2]

Steam updates only the in-game PWS plugin.

Claude Desktop users must also install the matching [code].mcpb[/code] from the [url=https://github.com/Distortik/pws-mcp-server/releases]GitHub release[/url] and restart Claude Desktop. Installing a newer package with the same extension identity normally upgrades the existing installation; uninstalling first should only be needed as a fallback. Regular Home-chat MCPB use remains blocked in beta.4 while beta.5 is developed.

Claude Code and Codex users can keep their MCP configuration pointed at the stable Workshop plugin folder. They can paste the setup request above into the client and ask it to locate, configure, and verify that path automatically instead of editing settings manually. Restart the client after an update so it reloads the current server and tool catalogue.
