[h1]PWS MCP Server Roadmap — What’s Coming in 0.5.0[/h1]

[h2]PWS MCP Server Roadmap[/h2]

Version 0.4.0 established the production foundation for safe save reads, show booking, wrestler personas, promises, stables, events, and verified changes. Development now moves toward 0.5.0: stronger approval guarantees, clearer client diagnostics, more accurate roster and hiring advice, and deeper booking and company-management tools.

This is a development roadmap rather than a guarantee that every candidate below will ship in one release. Features that change a save will only be included after their native PWS behavior has been established and tested safely.

   |

[/code]

[h2]Priority: safer and easier client workflows[/h2]

[h3]Preview-bound approvals[/h3]

Version 0.4.0 tools preview by default, require explicit confirmation, revalidate the live target during application, and verify the persisted result. For 0.5.0, the planned next step is a short-lived approval receipt that binds confirmation to the exact operation and target state shown in the preview.

This requires a coordinated change across every purpose-built write tool and client workflow, so it will be developed and tested as one system rather than added piecemeal.

[h3]Callable server and connection information[/h3]

A lightweight server-information tool is planned to report:

[list]
[*]The MCP client-server version.
[*]The expected in-game plugin version.
[*]The active transport and connection state.
[*]Whether the client and plugin versions match.
[*]Useful setup guidance even when no save is loaded.
[/list]

This should make update and connection troubleshooting easier for Claude Desktop, Claude Code, Codex, and other compatible clients.

[h2]Priority: roster, hiring, and popularity accuracy[/h2]

[list]
[*]Include Occasional Wrestlers consistently in relevant roster counts, filters, and hiring results while keeping angle-only roles clearly identified.
[*]Make hiring affordability account for available cash, payroll pressure, and the company's real top-end contracts instead of treating an estimated wage band as a hard limit.
[*]Expose regional popularity alongside continental popularity and warn when the two systems materially disagree.
[*]Investigate safe popularity management without masking unusual or invalid save states.
[/list]

Version 0.4.0 already detects PWS's advanced regional-popularity mode and uses the correct company-size calculation. The 0.5.0 work will make the underlying popularity data and any inconsistencies more visible.

[h2]Priority: deeper booking control[/h2]

[h3]Commentary-team defaults[/h3]

Preview-first management of brand and event-series commentary booths is planned. The current tools support announcers on individual segments, but they do not yet configure the intended default team stored on a brand or recurring event.

[h3]Multi-person entrance and elimination order[/h3]

Rumbles and other ordered multi-person matches need more than a winner. The investigation covers PWS's native [code]entranceOrder[/code] and [code]eliminationOrder[/code] data so future tools can safely describe and verify:

[list]
[*]Entrance numbers.
[*]Elimination sequence.
[*]The final two participants.
[*]The last eliminated worker.
[/list]

This will only move from investigation to implementation after the exact JSON written and consumed by PWS is confirmed.

[h2]Candidate company-management features[/h2]

[h3]Brands and championships[/h3]

Candidate tools would create, rename, configure, archive, or retire brands and championships with ownership checks and exact verification. Image handling needs separate investigation because PWS stores image filenames while the files themselves live outside the save database.

[h3]Tag teams[/h3]

Candidate tools would create, rename, edit, and disband promotion tag teams and manage their members safely.

[h3]Purpose-built action replacements[/h3]

The remaining advanced generic actions will be replaced gradually when their complete PWS contracts are known:

[list]
[*]Storyline creation.
[*]Worker signing.
[*]Championship awards.
[*]News creation.
[*]Email creation.
[/list]

Version 0.4.0 corrected and verifies the core generic worker-signing terms, but a proper preview-first signing tool still needs complete perk and negotiation behavior.

[h2]Larger systems requiring research[/h2]

[list]
[*][b]Contract negotiations and rival offers:[/b] renewals, offers, counters, matching, declines, perks, and negotiation states.
[*][b]Networks and TV deals:[/b] available networks, regional reach, show assignments, offers, acceptance, changes, and termination.
[*][b]Tournaments:[/b] tournaments, rounds, participants, matches, and links between booked segments and tournament records.
[*][b]Movesets:[/b] validated editing of the native worker moveset JSON and its supported move categories.
[/list]

These are valuable systems, but each touches several related tables or game actions. They are candidates for 0.5.0 research and beta work, not promises that every complete system will ship simultaneously.

[h2]The 0.4.0 foundation[/h2]

The current production release already provides:

[list]
[*]Company, roster, hiring, contract, worker, title, storyline, stable, venue, event, show, gimmick, persona, and promise reads.
[*]Complete show planning and validation with matches, angles, titles, ringside workers, referees, agents, announcers, and transactional segment editing.
[*]Contract-scoped wrestler personas and custom ring names without renaming workers globally.
[*]Preview-first verified tools for promises, stables, gimmicks, event series, show scheduling, venues, storylines, releases, and title vacations.
[*]Future-show availability based on injury, rehab, suspension, and time-off return dates.
[*]Official MCP SDK transport for Claude Desktop Home plus direct-path support for Claude Code and Codex.
[/list]

[h2]Known native constraints[/h2]

[list]
[*]PWS currently stores one active presentation per contract, not a separate persona selection for every match.
[*]A title or prize stored with [code]defendable = 0[/code] cannot be attached to a match. Book the match without it and award it afterward; a future purpose-built award tool should make that workflow preview-first and verified.
[*]Third-party plugins can replace native PWS functions or alter save data outside the MCP server. Compatibility work is safest when a mod exposes a stable, documented integration API.
[/list]

[h2]Client update reminder[/h2]

Steam updates only the in-game PWS plugin.

Claude Desktop users must also install the matching [code].mcpb[/code] from the [url=https://github.com/Distortik/pws-mcp-server/releases]GitHub release[/url] and fully restart Claude Desktop. Installing a newer package with the same extension identity normally upgrades the existing installation; uninstalling first should only be needed as a fallback.

Claude Code and Codex users can keep their MCP configuration pointed at the stable Workshop plugin folder. Instead of finding or editing the path manually, paste this request into Claude Code or Codex:

[quote]Locate the installed PWS MCP Server [code]mcp-server.js[/code] for the build I am actually using (Workshop, manual, or TEST). Configure your user-level MCP server named [code]pro-wrestling-sim[/code] to run it with Node, verify the saved entry, and tell me the exact path you selected. Do not guess the Steam library or edit unrelated MCP entries.[/quote]

Restart the client after an update so it reloads the current server and tool catalogue.
