[h1]Resolved: Claude Desktop MCPB Initialization Timeout[/h1]

[quote][b]Status: fixed and live-verified in 0.4.0-beta.5 on Claude Desktop for Windows.[/b][/quote]

[h2]What happens[/h2]

The 0.4.0-beta.4 PWS MCP Server MCPB installed, appeared enabled, and launched in Claude Desktop, but regular Home chats did not receive its tools. Claude Desktop sent the MCP initialization request, waited 60 seconds, and disconnected the extension before tool registration completed.

[h2]What was unaffected[/h2]

[list]
[*]The in-game PWS bridge and beta.4 save tools.
[*]Standalone Claude Code using the direct [code]mcp-server.js[/code] path.
[*]Claude Desktop's Code tab using its Claude Code MCP configuration.
[*]Codex using the direct [code]mcp-server.js[/code] path.
[/list]

The installed beta.4 server was byte-for-byte identical to the tested build and responded immediately when the same initialization request was replayed directly. This isolated the blocker to regular Claude Desktop MCPB startup rather than PWS save access.

[h2]Alternative direct-path setup without manual editing[/h2]

You can ask Claude Code or Codex to find and configure the correct path for you. Paste this request into the client you want to use:

[quote]Locate the installed PWS MCP Server [code]mcp-server.js[/code] for the build I am actually using (Workshop, manual, or TEST). Configure your user-level MCP server named [code]pro-wrestling-sim[/code] to run it with Node, verify the saved entry, and tell me the exact path you selected. Do not guess the Steam library or edit unrelated MCP entries.[/quote]

Approve the user-configuration change when prompted, restart that client, start PWS, load the intended save, and ask:

[quote]Use the PWS MCP server to show my current game state.[/quote]

Workshop and TEST plugin folder names remain stable across version updates, so the correctly configured path should not need to change every time. The client only needs to be restarted after updated files are deployed.

[h2]What beta.5 changes[/h2]

[list]
[*]Replaces the hand-written stdio layer with the official MCP SDK server and transport.
[*]Bundles that server into a self-contained file shared by the Workshop, direct-path clients, and MCPB.
[*]Passes automated initialization and catalogue tests through the official MCP client, including outside the repository without [code]node_modules[/code].
[*]Uses a dedicated MCPB entry point that starts correctly when Claude Desktop loads it through its Node UtilityProcess wrapper.
[*]Passed installation and confirmation in a fresh Claude Desktop Home conversation on Windows.
[*]Passed the matching beta.5 in-game version-pair and live read-only bridge checks.
[/list]

The beta.5 source server, standalone distribution, wrapper-loaded MCPB entry point, and Claude Desktop Home extension host all complete initialization. The successful Home conversation called the PWS integration and returned the loaded VWE1 state.
